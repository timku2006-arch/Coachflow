# CoachFlow

CoachFlow — веб-приложение (PWA) для фитнес-тренера и его клиентов: расписание тренировок, программы, результаты и графики прогресса. Интерфейс на русском языке, время московское (Europe/Moscow).

## Возможности

**Тренер**
- клиенты: список, создание профиля (email и временный пароль), рост, цель, заметки (видны только тренеру);
- программы тренировок для каждого клиента: упражнения, подходы, повторения, вес, дни; одна программа отмечена как текущая;
- расписание всех клиентов на неделю: создание, перенос и отмена записей без ограничений по времени;
- карточка результатов: за 15 минут до начала запись превращается в форму «упражнение / вес / повторения / подходы» с заметкой. Форма заранее заполнена из текущей программы клиента. Подходы можно вносить прямо во время тренировки: всё сохраняется само (сразу на телефоне и через секунду на сервере; без связи — досылается позже). Кнопка «Завершить тренировку» записывает результаты, списывает занятие с абонемента и уведомляет клиента. Пока тренировка идёт, на главной тренера есть карточка «Идёт тренировка»;
- длительность занятия 60, 75 или 90 минут: у каждого клиента своя по умолчанию (в профиле), при записи и переносе тренер может выбрать другую;
- удаление клиента вместе со всеми его данными (карточка клиента → «Удаление»);
- ориентиры по калориям и БЖУ;
- справочник упражнений и Telegram username в профиле;
- абонементы: оформить, исправить остаток, отметить оплату, история списаний;
- у каждой записи видно, подтвердил ли клиент приход: «Подтверждена», «Не подтверждена» или «Отменена»; кнопка «Клиент не пришёл»;
- у клиента в карточке: итог недели и месяца, значки, рекорды, замеры.

**Клиент**
- профиль (вес, рост, цель), текущая программа, история тренировок с результатами;
- графики: вес тела и рабочие веса по каждому упражнению;
- свои занятия в недельном календаре. Время чужих занятий показано как «Занято», без имён;
- запись, перенос и отмена занятий по правилу 3 часов (см. ниже);
- ориентиры по калориям и БЖУ (только просмотр);
- личные рекорды («Новый рекорд: жим лёжа 80 кг!»), значки достижений, итог недели и месяца на главной;
- замеры (вес, талия, бёдра, грудь, рука) с графиком и разницей с первым замером;
- «Осталось N занятий» по абонементу;
- напоминание за сутки с кнопками «Приду» / «Не смогу».

### Правило «окно в 3 часа»

Клиент может перенести или отменить занятие, только если до начала осталось **строго больше 3 часов**: при 3:01 можно, при ровно 3:00 и при 2:59 уже нельзя. Когда окно закрыто, вместо кнопок клиент видит сообщение и кнопку **«Написать тренеру в Telegram»** (`https://t.me/<username>`). На тренера правило не распространяется.

- Логика: `src/lib/booking-rules.ts`. Сравниваются абсолютные моменты времени (UTC), поэтому результат не зависит от часового пояса сервера.
- Проверка выполняется на сервере, в `src/server/services/sessions.ts` (`rescheduleSession`, `cancelSession`), независимо от интерфейса.
- Новое время записи или переноса для клиента тоже должно быть больше чем через 3 часа. Иначе клиент мог бы записаться на время, которое сразу нельзя изменить.
- Тесты: `tests/booking-rules.test.ts` (граничные случаи, другой часовой пояс сервера, переход через полночь) и `tests/sessions.integration.test.ts` (те же случаи через сервис и БД).

### Уведомления

- **Push на телефон** (Web Push) и **колокольчик** со списком в приложении.
- События: клиент записался, перенёс или отменил занятие (уведомление тренеру); тренер записал, перенёс или отменил занятие (уведомление клиенту); внесены результаты; обновлена текущая программа; изменились ориентиры по КБЖУ. Повторные правки за 10 минут схлопываются в одно уведомление.
- **Напоминания** за сутки и за 2 часа до тренировки клиенту и тренеру. Их рассылает фоновая проверка раз в минуту внутри сервера (`src/instrumentation-node.ts`), каждое напоминание отправляется ровно один раз. При переносе занятия напоминания сбрасываются.
- Ключи VAPID генерируются автоматически и хранятся в БД (`AppSetting`). Их можно задать и явно: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.
- На iPhone push работает, только если приложение добавлено на экран «Домой» (iOS 16.4+). Подсказка показывается в интерфейсе.
- Отключить фоновые напоминания можно переменной `DISABLE_REMINDERS=1`.

### Рекорды, значки, итоги

- **Рекорд**: лучший подход в упражнении тяжелее всех прошлых проведённых тренировок, а при том же весе — больше повторений. Первое выполнение упражнения рекордом не считается. Логика: `src/lib/records.ts`, проверка после сохранения результатов — `src/server/services/records.ts`.
- **Значки**: все правила в одном файле `src/lib/achievements.ts` (массив `ACHIEVEMENTS`). Чтобы добавить значок, допишите в массив код, название, иконку и условие. Значки начисляются автоматически после тренировки и при открытии главной клиента.
- **Итог недели / месяца** (`src/lib/summary.ts`, `src/server/services/summary.ts`): тренировки, пропуски, рекорды, рост рабочих весов, изменения замеров. Виден клиенту на главной и тренеру в карточке клиента.

### Абонементы

- При сохранении результатов тренировки с действующего абонемента автоматически списывается одно занятие (не больше одного раза за тренировку). Если подходит несколько абонементов, списывается тот, что заканчивается раньше.
- Когда остаётся 2 занятия или меньше, либо до конца 7 дней или меньше, клиент и тренер получают одно напоминание. Пороги — `src/lib/membership.ts`.
- Неявка («Клиент не пришёл») занятие не списывает. Если нужно, тренер исправляет остаток вручную.

### «Приду / Не смогу»

- За сутки до тренировки клиент получает push «Тренировка: завтра в 18:00. Придёте?». На Android в уведомлении есть кнопки «Приду» и «Не смогу». На iPhone кнопок нет: нажатие открывает экран с двумя большими кнопками.
- Пока клиент не ответил, на его главной показывается карточка «Придёте на тренировку?».
- «Не смогу» работает по правилу 3 часов: если времени больше, клиент одним нажатием отменяет занятие, иначе видит кнопку «Написать тренеру в Telegram».
- Если клиент сам записался, запись сразу считается подтверждённой. После переноса подтверждение сбрасывается.

### Фото прогресса (пока выключено)

Функция готова, но скрыта: флаг `PHOTOS_ENABLED` в `src/lib/features.ts`. Чтобы включить, поставьте `true` и настройте хранилище (см. ниже).

- Фото сжимаются на сервере (`sharp`): WebP до 1600 px и превью 480 px, данные EXIF (в том числе геолокация) удаляются. В БД хранится только ключ файла.
- Файлы видит только сам клиент и его тренер: они отдаются через `/api/photos/<id>` с проверкой прав.
- Хранилище (`src/server/storage.ts`):
  - **по умолчанию — папка на диске**: `UPLOADS_DIR`, по умолчанию `./data/uploads`, в Docker `/app/data/uploads`. На хостинге к `/app/data` нужно подключить **постоянный диск**, иначе фото пропадут при пересборке;
  - **или S3-совместимое хранилище** (Timeweb Cloud S3, Yandex Object Storage, Selectel). Для этого задайте `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` и `S3_REGION`. Бакет должен быть приватным.

### Другие правила
- Длительность занятия 60, 75 или 90 минут (по умолчанию 90). Клиент её не выбирает — подставляется длительность из его профиля. Активные занятия тренера не пересекаются: это проверяет сервис, а при одновременных запросах дополнительно срабатывает ограничение `EXCLUDE` в PostgreSQL.
- В системе один тренер. Регистрация открыта, пока тренера нет, после этого закрывается. Клиентов создаёт тренер, при первом входе клиент обязан сменить пароль.
- Права доступа проверяются на сервере в каждом сервисе: клиент видит только свои данные, тренер только данные своих клиентов. Чужие записи возвращают «не найдено».
- Все входные данные проходят валидацию через Zod (`src/lib/validation.ts`).

## Стек

Next.js 15 (App Router, Server Actions), TypeScript, PostgreSQL 16, Prisma 6, Zod, Tailwind CSS 4, Recharts, date-fns + @date-fns/tz, Vitest. Аутентификация: email и пароль (bcrypt), сессия в подписанном httpOnly-cookie (JWT, `jose`).

## Запуск

Нужны Node.js 20+ и Docker (или установленный локально PostgreSQL 16).

```bash
# 1. Зависимости
npm install

# 2. Настройки: скопировать и задать AUTH_SECRET (openssl rand -base64 32)
cp .env.example .env

# 3. База данных (PostgreSQL в Docker; заодно создаётся БД coachflow_test для тестов)
docker compose up -d

# 4. Миграции и тестовые данные
npx prisma migrate deploy
npm run db:seed

# 5. Запуск
npm run dev          # разработка: http://localhost:3000
# или
npm run build && npm start   # production-режим (включает service worker PWA)
```

### Тестовые аккаунты (после `npm run db:seed`)

| Роль | Email | Пароль |
|---|---|---|
| Тренер | trainer@coachflow.local | trainer123 |
| Клиент | anna@coachflow.local | client123 |
| Клиент | ivan@coachflow.local | client123 |

Seed строит данные относительно текущей даты: шесть недель тренировок с результатами и рекордами, одна прошедшая тренировка без результатов, одна отменённая, предстоящие записи, замеры и абонементы (у Анны он заканчивается). У Анны есть занятие примерно через 2 часа, на нём видно, как работает блокировка переноса и отмены. Seed можно перезапускать, но он **очищает** базу.

### Если PostgreSQL установлен без Docker

```sql
CREATE USER coachflow WITH PASSWORD 'coachflow' CREATEDB;
CREATE DATABASE coachflow OWNER coachflow;
CREATE DATABASE coachflow_test OWNER coachflow;
```

Миграция включает расширение `btree_gist`. Оно входит в стандартную поставку PostgreSQL и для владельца БД ставится без прав суперпользователя.

## Публикация (хостинг в России)

Зарубежные платформы (Vercel, Netlify и т. п.) из России работают нестабильно: часто медленно или только через VPN. Поэтому приложение собирается в Docker-образ и размещается у российского провайдера (Timeweb Cloud Apps, Amvera, Yandex Cloud, любой VPS с Docker).

- `Dockerfile` собирает образ. При старте контейнер сам применяет миграции (`docker/start.sh`) и запускает сервер на порту **3000**.
- Переменные окружения:
  - `AUTH_SECRET` (`openssl rand -base64 32`);
  - хранилище фото — только если включены фото: постоянный диск на `/app/data` или переменные `S3_*` (см. «Фото прогресса»);
  - подключение к PostgreSQL 14+ (лучше в том же дата-центре): либо одной строкой `DATABASE_URL`, либо отдельными полями `DB_HOST`, `DB_PORT` (по умолчанию 5432), `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_SSLMODE` (необязательно). Во втором случае пароль со спецсимволами кодировать не нужно.
- Во время сборки база не нужна.
- Если хостинг не разрешает расширение `btree_gist`, миграция пропустит ограничение на уровне БД, а пересечения занятий продолжит проверять сервер приложения.
- На рабочем сервере seed не запускается: тренер регистрируется сам через `/register`.

Проверка образа локально:

```bash
docker build -t coachflow .
docker run -p 3000:3000 -e DATABASE_URL="postgresql://…" -e AUTH_SECRET="…" coachflow
```

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер |
| `npm run build` / `npm start` | production-сборка и запуск |
| `npm test` | все тесты (unit и интеграционные на БД `TEST_DATABASE_URL`) |
| `npm run lint` / `npm run typecheck` | ESLint и проверка типов |
| `npm run db:migrate` | создать или применить миграцию в разработке |
| `npm run db:seed` | заполнить тестовыми данными |
| `npm run db:reset` | пересоздать БД и выполнить seed |

Тесты запускают миграции на тестовой БД и очищают её. Поэтому `TEST_DATABASE_URL` должен указывать на отдельную базу, в имени которой есть `test`.

```
  app/
    (auth)/              вход, регистрация тренера, смена пароля

tests/                   unit- и интеграционные тесты
```

## Модель данных

`User` (роль TRAINER/CLIENT) → `TrainerProfile` (telegram username) / `ClientProfile` (рост, цель, тренер) · `BodyWeightEntry` (дата, вес) · `Exercise` (справочник тренера) · `Program` + `ProgramExercise` · `Session` (время, статус, клиент, тренер, заметка) · `SessionResult` (подход: упражнение, вес, повторения) · `NutritionTargets` · `ClientNote` · `PersonalRecord` (рекорд) · `ProgressPhoto` (ключ файла фото) · `BodyMeasurement` (замеры) · `ClientAchievement` (значок) · `Membership` + `MembershipEntry` (абонемент и журнал списаний).

Время хранится в UTC (`timestamptz`), отображение и календарные расчёты ведутся в Europe/Moscow.

## Не входит в первую версию

Онлайн-оплата, встроенный чат, дневник питания, нативные приложения, SMS-напоминания.
